# Remote Display 1.0.16 — 가변 FPS 진단 버전

## 먼저 목표를 명확히

- **최소 기대치:** 사용 가능한 수준의 20~30 FPS
- **우선 목표:** 지연 없이 안정적인 60 FPS
- **가능하다면:** 60 FPS 초과도 허용 (모니터 주사율 및 시스템 상황에 따름)

이 진단은 **30 FPS를 목표나 최댓값으로 고정하지 않습니다.**
사용자별로 30 / 60 / 120 FPS의 *요청 상한*을 시험합니다.
Mac 서버에는 별도 네트워크 지연 기반 FPS 조절기(VideoQoS)가 있으므로
클라이언트가 60FPS를 요청해도 실제 전송 및 표시 FPS가 60이라는 뜻은 아닙니다.

## 안전한 테스트 절차

1. 현재 Remote Display를 **완전히 종료**합니다.
2. 기존 Remote Display 1.0.16 포터블 폴더를 **통째로 복사**합니다.
   원본 폴더에 있는 DLL은 절대 수정하지 마세요.
3. GitHub Actions 빌드 및 DLL 공개 함수 목록 호환성 검사가 둘 다 통과한 후에만,
   새 진단 패키지의 파일을 복사한 포터블 폴더에 넣습니다.
   `librustdesk.dll` 교체는 **포터블 복사본에서만** 수행합니다.
4. 같은 코덱·해상도와 비슷한 창 움직임으로 각 20~30초 정도 비교합니다.
   모드 전환 때마다 앱을 **완전히 종료**해야 환경변수가 반영됩니다.
   - `run-fps30-normal.cmd`: 기존 자동 FPS 제어 + 측정 로그
   - `run-fps30-force60.cmd`: Windows 자동 FPS 피드백을 우회하고 최대 60FPS 요청 (**주요 테스트**)
   - `run-fps30-force30.cmd`: 비교 목적으로 최대 30FPS 요청 (**기준 테스트**)
   - `run-fps30-force120.cmd`: 60FPS 테스트가 안정적이고 모니터 주사율이 이를 뒷받침할 때만 선택적 사용
5. FPS뿐 아니라 **입력 지연, 프레임 대기열, 네트워크 전송속도, 화질**을 함께 확인합니다.
6. **화면 반응이 더 느려지거나 프레임 대기열이 계속 증가하면 즉시 중단**합니다.
7. 원래 상태로 돌아가려면 진단 복사본을 종료하고 기존 포터블을 실행하면 됩니다.

## 진단 로그 확인

Windows의 Remote Display 로그 폴더: `%APPDATA%\RemoteDisplay`

`RD_FPS_DIAG`, `Set fps to` 문자열을 검색합니다.

- `mode=normal`: 기존 자동 FPS 제한 그대로 동작
- `mode=fixed-ceiling requested_fps_cap=Some(60)`: 60FPS 요청 상한 모드
- `displayed_fps`: Windows 쪽 실제 표시 프레임 수
- `decoder_capacity_fps`: 디코드 처리속도를 기준으로 한 추정 가능 속도
- `queue`: Windows 프레임 대기열의 현재 길이/용량
- `last_auto_fps`: 클라이언트가 마지막에 서버에 요청한 FPS 상한

이 진단값은 Mac의 **캡처 FPS / 인코딩 FPS / 실제 서버 전송 FPS**를 직접 측정하지 못합니다.

## 결과 해석

| 관찰 결과 | 가능한 해석 |
|---|---|
| 60FPS 요청 모드에서 실제로 40~60FPS가 되고 입력 지연도 안정적 | Windows의 자동 FPS 제어가 중요한 제한 요인이었을 가능성 |
| 요청만 60으로 바뀌고 실제 FPS는 5~11 유지 | Mac 캡처, 인코딩, 서버의 별도 QoS 또는 Windows 실처리 병목 가능성 |
| 표시 FPS는 올라가지만 대기열/지연 급증 | 처리량 또는 전송량이 실제로 따라가지 못함 |
| 120FPS 요청에서도 60 근처에서 제한 | 모니터 주사율, Mac 캡처율, 서버 QoS 등 추가 확인 필요 |

## 제한 사항

이것은 **진단용 빌드**이며 영구적인 성능 개선을 보장하지 않습니다.
DLL 공개 함수 목록 비교를 통과해도 런타임 호환성을 100% 보장하지 않습니다.
새 DLL을 기존 포터블 원본에 덮어쓰거나, 빌드 실패 후 일부 파일을 사용하지 마세요.
